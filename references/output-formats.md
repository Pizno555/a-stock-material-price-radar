# 输出格式

## 默认 Markdown

先输出标题、截止日期、监控窗口、候选数量和评分方法，再输出：

| 材料链 | 分类 | 发酵分 | 状态 | 核心催化 |
|---|---|---:|---|---|

表格按脚本结果原顺序展示，最多 30 条。不得在输出阶段重新排序或修改分数。

## 证据附录

每条候选按以下顺序展开：

1. 五项得分与总分。
2. 核心催化。
3. 价格、供给、A 股验证摘要。
4. 证据表：等级、日期、发布者、支持的事实、直达链接。
5. A 股映射：代码、公司、直接/间接、受益依据。
6. 反证。
7. 失效条件。
8. 数据缺口和高确定性门槛原因。

只引用确实支持相邻事实的来源。不要集中堆放链接，也不要引用搜索结果页。

## 本地网页

使用 `scripts/render_radar.py` 把评分 JSON 渲染为单文件 HTML。视觉规范：

把 `assets/reference-radar.png` 作为桌面视觉基准，不要把其中的示例文字或分数当作研究数据。

- 页面最大宽度约 1240px，浅暖灰背景。
- 顶部使用红橙色横幅、圆角和轻阴影；标题白色，元数据为半透明胶囊。
- 总览标题使用左侧红色竖线与圆形序号。
- 表头使用极浅红色背景；行间使用细分隔线。
- 评分使用橙到红的水平渐变条并显示整数。
- 高确定性使用浅橙徽章，发酵中使用浅蓝徽章，观察使用中性灰蓝，证据不足使用浅灰。
- 桌面端保持五列结构；窄屏将行变成卡片，确保催化、分数和状态可读。
- 证据附录置于总览之后，用折叠详情减少页面长度。

HTML 必须与 JSON 的分数、顺序、状态和缺口完全一致，不在浏览器端重新计算。

## PNG

先生成 HTML，再使用本地浏览器做全页截图。桌面参考宽度 1250px；需要与原图同密度时采用 1250×915 可视区，否则输出完整长图。不得使用生成式图片伪造表格文字。

## JSON

保留全部原始规范化事实、计算细节、门槛结果、缺口和排序。JSON 是 Markdown、HTML、PNG 的唯一数据源。
